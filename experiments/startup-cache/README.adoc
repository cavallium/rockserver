= Isolated startup/cache experiments

These fixtures use Java 25 FFM and one native runtime per process. They do not
change Rockserver service defaults or connect to production. All DB paths are
new local fixture directories. Output directories must not already exist.

== Cache restart reuse

Native patch `native/hot-cache-snapshot.patch` is commit
`34979508c36842d811f8900228951934a9efb061`, based on native
`cc8367a1076b6245574f209c7d007118cf9016b1` (tree
`82d609e8e224076fb5065679735ce8d6e14e5d22`). Apply it to that native checkout,
then follow `experiments/hot_cache/README.md` there to build the shim.
The qualified runtime is `librocksdbjni-linux64.so`, SHA256
`18d5865e39cccede36d63146eb9037837b423199930504e3730d2d91d9ff6214`.
An older cached library was ABI incompatible and is not valid for this probe.

[source,shell]
----
python3 experiments/startup-cache/run_hot_cache.py /path/to/libhot_cache_probe.so /new/local/cache-run
----

The harness compiles the standalone driver with `javac --release 25` and starts
seven separate JVMs. It verifies capture, reopen, recapture, another reopen,
and corrupt/truncated/missing snapshot fallback. Reports, exit codes, native
diagnostics and fixture storage remain in the output directory.

The initial fixture has one 16 MiB HyperClock cache and two CFs. A bounded
4096-key Insert/Lookup registry selects resident DATA/index/filter entries;
serialization and reconstruction stay native. The snapshot is capped at 64 MiB
with 1 MiB records and validated lengths/version/CRC before activation. The
generation is buffered before atomic publication, so capture RAM scales with
the cap. No cache handles are retained during SSD writes.

This proves actual cross-process reuse and corruption fallback, not production
HDD speedup. The registry includes initial inserts and misses pinned access
frequency. Per-CF hotness, dictionaries, async observation, separate data/metadata
quotas, cancellation/I/O budgets, compaction replacement, and crash-temp retention
are not qualified. Production integration must address those limits first.

== Asynchronous opening admission

Native patch `native/opening-admission.patch` is commit
`51d9fbfa183a4d6cc049d8e7b3089428c47e01c8`, based on the same `cc8367a` tree.
Build that checkout with the qualified native feature flags. The tested shared
library SHA256 is
`af39c1e03eb2b0ef304460a7601dae3b9ceab763b47cce77bad2ea7338a5c90b`.

The native admission patch adds an opt-in process-wide gate before `FindTable`,
outside DB/cache loading locks. Existing synchronous opening and foreground
reads bypass the gate. Pressure feedback halves the permit limit and spaces
admissions; healthy feedback increases the limit. Running opens finish, queued
workers observe shutdown and peer opening errors, and pressure still permits
eventual progress. This controls concurrency, not bytes or IOPS. Shared storage
and external feedback are assumptions of this first process-wide prototype.

[source,shell]
----
python3 experiments/startup-cache/run_opening_admission.py /path/to/librocksdb.so.11.8.1 /new/local/opening-run
----

The harness uses three fresh JVMs and the C API from the same native library:
seed 12 small SSTs, baseline asynchronous opening, and adaptive asynchronous
opening. The read fixtures explicitly skip synchronous opening-statistics
initialization, so it cannot pre-open all SSTs before the asynchronous worker.
The adaptive fixture starts under commanded pressure, then supplies measured
50 ms foreground p95 windows against twice the baseline's last-window p95.
It verifies read values and that permits/waiters disappear before library close.

The first final run completed 12 admitted operations, with peak admission 3
and final limit 4. It applied 39 healthy windows; no naturally pressured window
occurred. This is a small warm/page-cached fixture with a debug native library
and FFM overhead. Its timings are not a production performance comparison,
and admission counters do not attribute physical HDD reads. Native deterministic
tests separately exercise forced pressure, foreground access while admission
waits, failure cancellation, and shutdown: four focused tests passed 100 repeats,
56 existing asynchronous-opening tests passed with the gate disabled, and the
combined 60-test selection passed with the gate enabled. Full native-suite and
io_uring-path acceptance were not run; local io_uring initialization fell back.
Feedback integration with the actual
Rockserver scheduler and device-aware policy remains future work.
