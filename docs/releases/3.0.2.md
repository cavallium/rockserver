# Rockserver 3.0.2

Maven coordinates: `it.cavallium.rockserver:rockserver-core:3.0.2` and
`it.cavallium.rockserver:rockserver-distributed:3.0.2`. The wire protocol, the config format, the native library
(`it.cavallium:rocksdbjni:11.8.1.14`) and the on-disk format are unchanged from 3.0.1: a 3.0.1 client works with a
3.0.2 server and the other way round, and a cluster is upgraded one node at a time.

## Operator output

- **`admin` on a terminal.** `status` prints a verdict (`HEALTHY`, `DEGRADED`, `NO LEADER`, `ELECTION`, `NO QUORUM`)
  and a table with one row per member: role, applied and commit index, how far it is behind, its Raft address. The
  other commands mark each line (`·` progress, `!` a warning or a retry, `✓ OK` with the elapsed time, `✗ FAILED`),
  print the members' results of `checksum` and `backup` as a table, and show one line while they work. `admin help`,
  and `admin` with no command on a terminal, list the commands. A wrong call shows those commands and then its
  reason. Colors are off with `NO_COLOR` or `TERM=dumb`.
- **Scripts are not affected.** Piped or redirected, every command prints exactly the lines of 3.0.1. `--plain` and
  `--pretty` force one or the other.
- **Quiet one-shot commands.** `admin`, `export-seed`, `build-seed` and the other one-shot commands print the
  libraries' messages only from "warn" up.
- **`distributed/deploy/rs-admin`.** The admin command for a node that runs as a systemd service. It holds no
  setting: it reads the Java, the classpath, the group id and the members from the unit's command line.
- **The node's periodic log.** Every 10 s a node logs what it did in words, on three lines at most: a heading, a
  `work` line (entries applied, client writes, commits, reads, per second, with average and slowest time) and a
  `health` line (delay from the leader's log to the apply, backlog, transaction conflicts, open transactions, heap).
  An idle node logs one line. The former line with every series is logged at debug level
  (`-Dorg.slf4j.simpleLogger.log.it.cavallium.rockserver.distributed.NodeMetrics=debug`); the exported metrics are
  unchanged.
- **Log line prefix.** A node's log lines no longer start with the thread name and the full package of the logger
  (`INFO NodeMetrics - ...`), unless `org.slf4j.simpleLogger.showThreadName` or `showLogName` is set.

## New metrics: deadline cleanup of retained resources

Exported by the core (single node and every cluster member), tagged `db` and, where it applies, `resource`
(`transaction`, `iterator`, `range`):

| Metric | Meaning |
|---|---|
| `rockserver.active.native.ops` | Admitted operations in progress, without the retained resource leases |
| `rockserver.resource.leases` | Retained resource leases (open transactions, iterators, range cursors) |
| `rockserver.resource.overdue.count` | Entries past their deadline that the cleaner tried to close and that are still retained |
| `rockserver.resource.oldest.overdue.seconds` | The largest deadline overrun among those entries |
| `rockserver.resource.cleanup.scan.age.seconds` | Time since the cleaner last completed a pass |
| `rockserver.resource.cleanup.failures` | Closes of expired resources that failed |

The first three per-resource gauges are measured by the cleaner's own pass and cached: a scrape never walks the
resources. They are NaN until the first pass. A range can stay in `overdue.count` for a short time on a healthy
node, while native work in flight ends: alert on `oldest.overdue.seconds` and on `cleanup.scan.age.seconds`, not on
the count.

## Fixes

- `build-seed` accepts the cluster's own config: the stanzas of the columns it imports no longer make the import
  fail ("Column family already exists").

## Tests

- The slow tests are opt-in (`-Pslow-tests`, which CI uses); the default run takes about a minute and a half.
