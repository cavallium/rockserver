# Rockserver 3.0.1

Maven coordinates: `it.cavallium.rockserver:rockserver-core:3.0.1` (the server, the embedded engine and the client)
and `it.cavallium.rockserver:rockserver-distributed:3.0.1`. The wire protocol and the config format are unchanged
from 3.0.0.

## rocksdbjni 11.8.1.14

The native library is `it.cavallium:rocksdbjni:11.8.1.14` (was 11.8.1.13). It adds these native patches:

- **0023:** a column family whose merge operator is missing returns `InvalidArgument` for a merge.
- **0024:** a failed pinned `Get` throws a Java exception instead of aborting the JVM.
- **0025:** `Checkpoint::ExportColumnFamily` honours `cf_paths`: it takes each table file from the directory its
  column keeps it in. `build-seed` and `EmbeddedDB.exportColumn` no longer put a symbolic link per table file in the
  database directory for the time of the export; that Java workaround is removed. A killed `build-seed` no longer
  leaves `*.sst` symbolic links or `column-export.*` in the source database directory.
- **0026:** a column family import syncs the files it imports.
- **0027:** a lock around the loading of table metadata, so a background-priority load no longer blocks user reads.
- **0028:** the compaction read service time is measured with a monotonic clock, so it survives wall-clock steps.

## Adaptive compaction I/O budget

`database.global.adaptive-compaction-io=true` enables the controller; see `docs/adaptive-compaction-io.md`. It stays
off by default and has not been validated on a real RocksDB under production load.

- A window that did not saturate the limiter no longer lowers the budget, and a saturated healthy one doubles it. This
  fixes a budget of 40,960 B/s that lasted 12 minutes after a tiny first flush.
- Two consecutive slow windows lower the budget to 0.7 times the achieved rate, at any utilisation. A growth step
  followed by a slow window is taken back.
- Growth is in two phases around the rate at which harm was measured: +10% of it per window up to 90%, then +5% every
  6th window. A decrease is followed by a hold of 3 windows. One slow window after a doubling is not remembered as a
  harmful rate unless the retried doubling is also taken back.
- A rate trial from a healthy state runs only to calibrate the baseline after a start or while the read pool is
  saturated. No trial starts from a window under 80% of the budget, and nothing takes the budget under the limiter's
  seed.
- The point-read baseline may rise to at most 1.2 times its lowest level, instead of following a slow degradation
  without end. Slow reads over a background at or under the flush floor become the baseline again.
- Urgent pressure never lowers the budget, also when it arrives from the BOOTSTRAP state.
- The budget floor rises with compaction debt (pending compaction bytes and L0 files) from debt 0.5, to the last known
  service rate at debt 1, instead of acting only at a write stall.
- The limiter is rewritten only for a change of 5% or more.
- While writes are stopped or delayed, the limiter is unlimited from the poll that sees it until 10 s after the last
  stall poll, so that a flush that started before the stall gets its tokens. Nothing is learned from those polls, and
  the budget in force before the stall returns afterwards. New state UNLIMITED (4) of the state gauge.
- The control law has randomized property tests over a small model of a server (`CompactionIoBudgetInvariantsTest`).
