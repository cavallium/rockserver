# Rockserver 2.1.0

Adds live SST metadata and selective same-level `CompactFiles` through the embedded
Java API and gRPC, with a dry-run-first example script for adjacent L5/L6 packing.
The API validates sessions, adjacency, shared boundaries, busy inputs, output paths
and observed input budgets. Native execution retains DB/column ownership until it
returns and runs on the physical-maintenance scheduler.

Maven coordinates: `it.cavallium.rockserver:rockserver-core:2.1.0`.
Build with `-Drevision=2.1.0`; the repository retains its existing CI-friendly
`${revision}` development version convention. RocksDB JNI remains 11.8.0.1.

See [API and script usage](../selective-sst-compaction.md). The observed input budget
is not a hard post-expansion native I/O limit. Per-job native cancellation and durable
job status are not included. Thrift explicitly reports this API as unsupported.

## Release validation

- 3,065 standard Java tests: zero final failures/errors/skips.
- 18 fuzz regression tests: zero failures/errors/skips.
- Four Python selector tests: passed.
- Standalone fat JAR built successfully with version 2.1.0 embedded.
- Actual Python/grpcurl smoke against that JAR on a disposable local database:
  validation of six L6 inputs without mutation, execution producing one output,
  then refreshed inventory finding no further eligible group.

The full selected standard run found one missing explicit wire-policy inventory
entry for `compactFiles`. That test inventory was corrected and its eight tests
were recompiled and rerun successfully. All other selected standard tests passed
in the broad run; no product code changed after that run. The earlier intermittent
reactive-range lifecycle assertion was made deterministic by blocking at actual
column-lease acquisition instead of downstream delivery, which can outlive a
prefetched native cursor. Its class passed both the focused and broad release runs.

Three unchanged expensive scheduler state-space model classes were excluded:
`WorkloadPressureControllerConcurrentExhaustiveTest`,
`WorkloadPressureControllerExhaustiveTest`, and
`OnePoolSchedulerArbitrationExhaustiveTest`. The scheduler algorithm was not changed;
the command-admission and wire-policy matrices, scheduler regression tests and new
compaction integration tests were included. This is not a claim that every possible
repository test or hardware performance gate was rerun.
